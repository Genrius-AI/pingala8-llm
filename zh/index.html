面向本地大模型的开源 2-bit 压缩

我们把大模型压缩了 85%。 与 llama.cpp 的 2-bit 一样大，却聪明得多。

Pingala-8 把 Qwen3-4B 存成 1.24 GB，而原始模型是 8.05 GB。这与 llama.cpp 最小的常用 2-bit 格式 IQ2_XXS 的文件大小相同，而它在五项标准测验上的得分高出 21%。无需重新训练：它直接压缩你手上已有的模型。代码、日志和 Windows 一键包全部公开。

试用

3 步试用

需要 Windows 或 Linux，一块 NVIDIA RTX GPU（30、40 或 50 系列）和较新的驱动程序。无需 Python，无需编译。

注意：原版 llama.cpp、Ollama 和 LM Studio 目前无法加载这些文件，请使用一键包里修改过的 llama.cpp。

  1. 下载

    从 v2.4-oneclick 发布页 下载 pingala8-windows-cuda12.zip（1.6 GB）。

    Linux：同一页面上的 pingala8-linux-cuda13.tar.gz。

  2. 解压并双击

    运行 run_qwen3_4b.bat（或 run_llama31_8b.bat）。模型会从 Hugging Face 下载一次。

    Linux：./run.sh qwen 或 ./run.sh llama。

  3. 聊天

    在 Windows 上，浏览器会打开聊天页面 http://127.0.0.1:8080（在 Linux 上请自己打开这个地址）。一切都在你的电脑上运行。

    关闭黑色窗口即可停止。

从源码构建、运行论文中的困惑度测试，或使用 CPU 补丁：请参阅 README 中的快速入门（英文）。模型：Qwen3-4B 和 Llama-3.1-8B。

工作原理

作用于每组 4 个权重的网格码（trellis code）

大多数 2-bit 格式对每一小组权重单独取整。Pingala-8 用 Ungerboeck 的 8 状态网格码按顺序对各组编码：一个很小的状态从一组 4 个权重传到下一组，并决定下一组可以使用哪一组取值，所以同样的比特能更接近真实的权重。

编码之前，随机 Hadamard 旋转会把少数特别大的权重分散开，LDLQ 取整则把每一列的误差传给尚未编码的列。这些思路来自 QuIP、QuIP# 和 QTIP，这种格式与 ikawrakow 的 IQ2_KT 相近。llama.cpp 的一个 CUDA 补丁（commit 7ac59a6）负责读取这个文件。

阅读完整文章（英文），了解通俗的解释和技术细节。

名字的由来

Pingala 的 Chandahsutra 是一部论述诗歌格律的古代梵语著作，书中列出了由三个长音节或短音节组成的 8 种模式，即 gana。我们的编码在短模式上有 8 个状态，所以用他的名字命名。这个名字是一种致敬；网格的标签来自 Ungerboeck。

局限

我们的不足

选择 Pingala-8 之前，请先读完这一部分。

  • 在 Qwen3-14B 上落败。我们在运行前预测会胜出，结果没有：在 WikiText-2 上为 9.57，IQ2_KT 为 9.40；在 C4 上打平。
  • 提示词处理更慢。读取提示词的速度是 IQ2_XXS 的 0.74x。长文档在输出第一个字之前要等更久。
  • 批量解码更慢。同时服务 2 到 8 个对话时，速度是 IQ2_XXS 的 0.18x 到 0.34x。它适合一个人用一块 GPU，不适合做服务器。
  • 需要我们的运行时。仅支持带 CUDA 的修改版 llama.cpp。原版 llama.cpp、Ollama 和 LM Studio 目前还无法加载。不支持 Metal 或 Vulkan；CPU 生成速度是 IQ2_XXS 的 0.56x 到 0.62x。
  • Qwen3-4B 的数字经过调优。这个文件是在 WikiText-2 上测试过的众多构建中的最后一个。C4 是留出的测试集；Llama-3.1-8B 和 Qwen3-14B 的运行都是预先登记的。
  • 只测了一块 GPU，没有安全评估。速度是在一块 RTX 5070 Ti Laptop GPU 上测得的。我们没有评估压缩后模型的安全行为。
